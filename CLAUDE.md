# Varde – project notes for Claude Code

Varde (working name, may change) is an offline web app (PWA) for planning and packing outdoor trips: day hikes and shorter multi-day hikes with tent or under the open sky. Owner: Svein Atle. Published with GitHub Pages by a GitHub Actions workflow, only after the smoke test passes on `main` (from build 59, see Publishing).

## Files
- `index.html` – the whole app (HTML, CSS and JavaScript in one file). No build step, no external dependencies apart from Google Fonts.
- `sw.js` – service worker that makes the app work offline. Contains the cache name `CACHE` with the build number (`varde-b33` and so on).
- `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png`, `icon.svg` (browser tab) – installation on the phone; all built by `tools/make-icons.js` from `design/icons/` (see «App icon»).
- `design/icons/landscape-*.svg` – the icon landscapes (dusk, night, sunset; from build 85). Not loaded by the app; the ridges are copied into `index.html` for the landscape on Innstillinger (build 88).
- `tools/make-icons.js` – builds the icon files from one landscape (from build 85). Not part of the app.
- `README.md` – short user guide (Norwegian).
- `tools/csp-hash.js` – keeps the script hash in the Content-Security-Policy tag up to date (from build 58). Not part of the app.

## Structure of index.html
- `UI` – all interface text, in `en` and `no`. Every new string must be added in both.
- `friluftsliv(L)` – the template list (main sections in the order Før tur, Overnatting, Generelt turutstyr, Tøy, Matlaging, Mat; Tøy above Matlaging from varde-v28), written as `[Norwegian, English]` pairs. Prefixes in item strings: `> ` = sub-item, `* ` = included in the light day-hike view, `@key ` = links to a bag list.
- Main sections, trip modes (`mode:`), and bag lists (`bag:true`: Forberedelser, Førstehjelpssett, Reparasjonssett, Personlig pleie). A non-sub item followed by sub-items is rendered as a subheading and is not counted.
- `MODES` (trip types), `CAT_ICONS` (section icons), `SKINS` (Fjell, Mose, Fjord, Sommereng, Berg, Lett bris; the last two from varde-v27). Berg has a faint stone grain (`--grain`, an inline SVG noise, so it works offline) on the page and header, switched off in Nattlys. Lett bris (from varde-v28): cream page, light sky-blue header with dark header text, summer-blue accent, own `--gsafe` (orange). A light header sets `--hd-btn` (list button background) and `--hd-track` (progress bar track) so they stay visible; Nattlys resets both.
- Tabs: Pakkliste, Notater, Planlegg (Mat, Drivstoff, Sekkvekt, Vannblanding, Vindkjøling), Guider (grouped: Ferdigheter i felt (Dyrespor last, from build 43): Knuter, Tarp, Sove godt på tur, Pakk sekken, Kart og kompass, Fiske, Bål; Vær og sikkerhet: Solbriller, Vinterråd, Topptur og skred, Møte med dyr (from build 45); Utstyr og vedlikehold: Telt, Reparasjoner på tur, Brennerplate, Skalltøy, Fjellsko, Ski: smøring og feller, Mobilen på tur; Helse og nød: Medisiner på tur (from build 42); Himmelen (from build 60): Retning om natta, Nattehimmelen, Nordlys; Sove godt på tur and Ski from build 36, Pakk sekken and Reparasjoner på tur from build 37, Kart og kompass from build 38), Kompass.
- **Tapping the tab you are on (from build 36):** on a sub-page it goes to that tab's main view, as before; on the main view it scrolls to the top (`scrollTopSmooth()`, smooth, instant with reduce motion). Navigation only: ticks and fold states are untouched, and in Regnlås it renews the navigation window.
- Utemodus (outdoor mode): larger targets, editing locked, Lås listen switched on, screen kept on, strict tap filter, the Utemodus sign and Regnlås in the header, and the light row: Rødt nattlys, Grønt nattlys and Bål (from varde-v30; Angre and the Regnlås chip under Utemodus were removed then).
- Data is stored in `localStorage` under `KEY`. Every write goes through `persist()` (`save()` = `bkTrack()` + `persist()`); never call `localStorage.setItem(KEY, …)` directly.
- **Data safety (from build 63, 0.14.1):** if the stored text cannot be read, `load()` copies it unchanged to `KEY + '-rescue'` (`RESCUE_KEY`, only if no copy is there yet, so a later start never overwrites it) and the app starts empty. After the introduction a notice (`rescueQ`, `rescueMsg`) offers Sikkerhetskopi, where a section «Data som ikke kunne leses» shows the copy as text with Kopier and Slett kopien (`rescueText()`). A failed save (full storage, private mode) shows the `saveFail` toast once per session (`saveWarned`).

## Data model (from varde-v7)
- `state.v = 2`. Older stored data is converted once by `migrate()`; lists that match the built-in template become the standard list (ticks, trip types and views kept), anything else is kept as an own list. Never remove the migration.
- **Standard list:** built from `friluftsliv(lang)` on the fly by `stdList()`, always in the app language. Its ticks, trip types, light view and folded sections live in `state.std` (`done`, `modes`, `light`, `open`). Item ids are `std:<section key>:<Norwegian text in lower case>`, so ticks survive a language switch; changing the Norwegian text of a template item resets that item's tick.
- **Own lists:** `state.lists`. `state.main` is `'std'` or the id of the own list shown on the front page (Bruk som hovedliste). `list.tripType` makes it appear under Turtype (Legg til i turtype). The two roles rule each other out: making a list the main list switches its trip type off, and making the main list a trip type, or switching its main role off, falls back to the standard list; switching it on stores `'L:<list id>'` in the main list's `modes`, and its sections are added to the main list.
- Always change ticks, folding and light view through `setDone`, `setOpen` and `setLight`, which handle both kinds of list.
- **Sharing:** `#share=<code>` links carry a packed list (`packList`/`unpackList`), deflate-compressed when the browser supports it (`z` prefix) or plain (`j`). Nothing is stored on a server.
- **Introduction:** shown once (`state.introDone`), and from Guider → Slik bruker du Varde.
- **Fuel planner:** litres boiled per person per day (`USE_KEYS`, defaults in `WATER_DEFAULT`, drinking water is always boiled) times fuel per litre (`FUELS[x].perL`: gas 15 g, petrol 30 ml, spirit 50 ml; own figure in `fuelCalc.perLc`). Water from snow multiplies everything by `SNOW_BOIL` (2.5). Day hike mode (`fuelCalc.mode = 'day'`) hides the table and uses one figure (`dayL`). The summary at the top shows the whole calculation.
- **Food planner:** meals per person per day with their energy side by side; the gauge at the top shows one full day against zones (`KZONES`: summer red below 2000 kcal, yellow below 3000, green above; winter 2500 / 3500).
- **Guide drawings:** own drawings (no licence needed) in `guides/`, loaded inline by `loadSvgs()` and coloured with `--sb-*` variables (defined on `.sb-fig`, with dark, Rødt and Grønt nattlys values; `--sb-heavy` from build 37 for the heavy zone in Pakk sekken); precached in `sw.js`. From build 37 a text guide section can hold a drawing: `<figure class="sb-fig"><div data-svgsrc="guides/<file>.svg"></div></figure>` in its HTML; `renderTextGuide()` calls `loadSvgs()` and passes every section through `planLinks()`. Drawings carry no text (both languages) and use `var(--sb-surface)` instead of white, so the night lights stay pure red or green. Drawings in build 37: `firesteel.svg` (Bål → Tennstål), `pack-zones.svg` (Pakk sekken), `edge-repair.svg` (Reparasjoner på tur); build 38: `compass-parts.svg` (numbered, with a `.fig-legend` list in the same figure) and `compass-steps.svg` (Kart og kompass). Web links in guide text: write `[[web:<url>|<label>]]`; `renderTextGuide()` turns it into a `webLink()` row through `webMarks()` (from build 38; used for norgeskart.no).
- **Notater (notepad, from varde-v18):** `state.notes` = `[{id, title, text, t}]`, newest first by `t` (last edited). Pages: `notes` tab, one note at `note:<id>`. Opening a note is navigation (`data-nav`); new, edit and delete are data changes and are hidden in Utemodus. Delete uses `withUndo`. Lists no longer have their own notes: `notesFromList()` moves any list notes into the notepad (once for stored lists, `state.notesMoved`; and for lists received by share link or restored from backup), titled with the list name. The backup carries `notes` beside `lists`.
- **Notater from build 41 (0.6.0):** *Edit in place:* on a note's own page, Rediger (removed in build 87), the title or the text (`data-act="editNote"`, `data-f`) turns the note into fields in place (`#neTitle`, `#neText`, the text box grows with `growArea()`), with Avbryt and Lagre below (`noteCancel`, `noteSave`). The draft lives in `noteEdit` (never stored); from build 81 leaving it saves it (see «Notes save themselves»); Lagre only changes `t` when something changed, and an empty title and text are not saved. The pop-up `askNote()` is only for Nytt notat. A tap while text is selected does not start editing. *Fest øverst:* `n.pin = true` (`notePin`, the same button unpins); `notesSorted()` puts pinned notes first, each part newest first; a small pin (`PIN_IC`) shows in the list and on the note. *Del:* `noteShare` → `askShareNote()`: the sheet shows exactly what is sent (title and text), the warning about personal information and an optional name field, empty by default and never remembered; then Rediger først (opens the edit in place) or Del. The link is `#note=<code>` with `{v:1, k:'note', ti, tx, n?}` packed by `encodePacked()` (shared with list links); nothing else goes in. On a successful share `n.shT` is set. Opening a link runs `receiveNote()` from `checkShared()`: it shows the note and asks «Legg til i notatene dine?»; an identical note already there is opened instead. A received note gets `n.rcv = {n:name, t}`. *Tags:* `noteTags()` gives «Delt fra [navn] · [dato]» or «Mottatt [dato]» and «Delt [dato]», in the list and on the note. Received notes have a dashed outline in `--muted` (class `rcv`), never the accent colour; the tag says the same in words. Pin, edit, share and delete are hidden in Utemodus and locked in Regnlås (no `data-nav`). Backup: the notes carry `pin`, `rcv` and `shT`; `noteMeta()` copies them on restore, and `personalSig()` counts `pin` and `rcv` only when present, so older backups are not flagged as changed.
- **Sekkvekt (pack weight, from varde-v19):** `state.packW` = `{unit:'g'|'kg', items:[{id, name, g, cat, cons, dog}]}`; weights are always stored in grams, `unit` only changes display and input. Items come from the main list (`pickFromList()`, food items marked as consumable) or are typed in (`askWeightItem()`, category from the main list's sections or Annet). The summary shows the total of your pack, base weight and consumables (when anything is marked consumable), a subtotal per category, and the dog pack separately. Always go through `packW()`.
- **Dog in the planners:** food planner shows kcal per meal next to each meal name (`data-mk`, from varde-v22); `foodCalc.dog`, `dogs`, `dogG` (g per dog per day, times days including the reserve day; not part of the kcal gauge). Fuel planner `fuelCalc.dog`, `dogL` (litres per day), only when water comes from snow: added once per day, not per person, times `SNOW_BOIL`.
- **Start på nytt (from varde-v20):** button in Innstillinger, the last section of its first part (from build 80; before that on Dine lister), hidden in Utemodus. Clears all ticks (standard list, own lists, bags), all trip types, Lett dagstur on every bag (from build 48), the Kompass fold-outs in `state.folds` (back to default; from varde-v26), folds the Turtype panel, applies the start state (`foldStart()`, every category folded; from build 48), makes the standard list the main list, and turns off Utemodus, Regnlås, Nattlys (from build 48), Skjul pakket and Lås listen. Never deletes lists, notes, Dine lenker, Sekkvekt, planner figures, the saved position or settings (language, skin, theme, the Kompass sun and moon toggles), and never shows the introduction again. Runs through `withUndo`.
- **Knot pictures:** an entry in `KNOT_FILES` can be one file or an array of files (several pictures on one card, as for Åttetallsknute). Every picture needs a line in `KNOT_CREDITS` (two lines with the same `k` are fine) and a place in `sw.js`.
- **Fonts (from varde-v22):** Barlow 400/600 and Barlow Condensed 600 are bundled in `fonts/` (latin subset, from Fontsource; SIL Open Font License, `fonts/OFL.txt`) and loaded with `@font-face`, so the app looks the same offline. No Google Fonts or other outside requests. New font files must be added to `sw.js`.
- **Text guides:** plain text guides (Skalltøy, Fjellsko with Skistøvler, Telt, Tarp, Bål, Topptur og skred, Sove godt på tur (`sleep`), Ski: smøring og feller (`ski`, sections `wax` and `skins`), Pakk sekken (`pack`, section `zones`), Reparasjoner på tur (`repair`, sections `patch`, `pad`, `pole`); Kart og kompass (`mapcompass`, sections `parts`, `steps`, `decl`, `maps`; from build 38, linked from the list line «Kart og kompass i vanntett kartmappe» and from a button under Om kompasset on Kompass); Bål has the section `steel` (Tennstål) from build 37) live in `GUIDE_TXT` (`no` and `en`, each `{title, short, sub, secs}`; a section can carry a third value as its id) and are drawn by `renderTextGuide()`. Kept in their own object, not in `UI`, so their keys cannot clash with interface text. A new text guide only needs an entry in both languages and a place in `GUIDE_GROUPS`.
- **Søk i Guider (from build 39, 0.5.0):** on the Guider page a magnifier button (`.gs-btn`, `data-act="gsOpen"`, 48 px) sits at the right of the intro line «Korte påminnelser til turen.». Tapping it swaps that line for the search field (`#gsInput`, `.gs-field`) with focus and the keyboard up; × (`gsClose`) clears and closes it, an empty field closes by itself when it loses focus, and tapping the Guider tab or leaving Guider clears the search (`gsReset()`). State lives in `gSearch` (`{open, q}`), never in `state` and never stored. From two letters (`GS_MIN`) the groups are replaced by a count and results (`gsShow()`, only `#gsBody` is redrawn while typing, so the field keeps focus); below that the groups show. Matching (from build 40, 0.5.1): both languages whatever the setting, case ignored, parts of words match, words not meanings. A match in the current language is shown as usual; a match found only in the other language shows that language's snippet with a small tag (`.gs-lang`, «NO» or «EN») and still opens the section in the current language. `guideIndex(lang)` builds the plain text per guide (title, short, intro, sections) once per language (`gsCache[lang]`), using `gsPlain()` (markers and tags out, entities decoded in an inert document). Each result (`.gs-hit`, left stripe in the group colour, guide name, section name, snippet with every match in `<mark>`) is one section, or the guide's top for a hit in its title or intro; at most `GS_MAX` (50) are shown. A result is navigation (`data-nav`, `data-act="gsHit"`): it opens the guide, then `openHit()` unfolds the `<details>` whose summary contains the section heading and scrolls it into view; Back returns to the open search with the same text. Typing, opening and closing the field are locked in Regnlås (the magnifier and field are greyed); results already on screen work in the navigation window.
- **Rule: every guide and section is searchable.** A text guide in `GUIDE_TXT` is searched automatically. A guide with its own renderer (Knuter, Fiske, Solbriller, Vinterråd, Brennerplate, Mobilen på tur) is listed in `old` inside `guideIndex()`: add any new text it shows there, and give every new guide with its own renderer an entry. Section headings in the index must match the `<summary>` text the guide draws, or the result cannot unfold its section. Sections are matched between the languages by position, so every guide keeps the same sections in the same order in Norwegian and English (the smoke test checks the counts).
- **Guider groups fold (from build 64, 0.15.0):** each group heading keeps its look (name in the group colour, thin line, now 1.5rem) and is a fold button (`button.ix-group`, `data-gfold`, `data-nav` so it works in Regnlås, `aria-expanded`, `aria-controls="gx-<key>"`) with the number of guides and a chevron at the end of the line; while folded, a muted line under it names the first three guides. The click handler folds in place (`.index.gf-closed`) without a redraw. Open groups are kept in `state.gOpen` and cleared by `foldStart()`, so a fresh start shows every group folded. `go()` opens the group of any guide it opens (from the index, a link or search), so Back lands on an open group. A group with `fixed:true` in `GUIDE_GROUPS` would never fold and stay an `h2`; none has it. Helse og nød folds like the rest from build 65 (0.15.1, decided 16 Nov): the Nødmodus button sits above the groups and links to Nødsituasjon, and five groups look cleaner all folded. Each group has a line icon before its name (`GROUP_ICONS`, from build 65): axe (Ferdigheter i felt), sun behind a cloud (Vær og sikkerhet), moon and star (Himmelen), tent (Utstyr og vedlikehold), the heart (Helse og nød). Same style as the heart: 24 × 24, stroke only, `currentColor`, so they take the group colour and the night light. The axe is drawn upright and placed with a `matrix()` that turns and scales it to fit, with a compensated `stroke-width`. A new group needs an icon here. Several groups can be open at once; no Åpne alle / Lukk alle. Smoke tests open a guide row with `openRow()`, which unfolds its group first.
- **Guider order (agreed 17 Oct 2026):** groups are ordered by how often Guider is opened directly: Ferdigheter i felt, Vær og sikkerhet, Utstyr og vedlikehold, and later Helse og nød (mostly reached by links). Within a group, the most-used guide first, and guides that link to each other side by side. A new guide goes into an existing group by when it is used: out on the trip → Ferdigheter i felt; before the trip or at home → Utstyr og vedlikehold. A new group only for a clearly new use with at least three guides. Each guide sits in one group only; link between guides instead of copying text (`data-act="openGuide" data-guide data-sec`).
- **Guide groups:** `GUIDE_GROUPS` sets the order and group of every guide on the Guider page. Order (from varde-v21): Ferdigheter i felt first (what you look for in a hurry), then Vær og sikkerhet, and Utstyr og vedlikehold last (what you check back home). Each group has a colour (`--gc`: `--lichen`, `--red`, `--gsafe`) shown as a stripe and a group heading, never colour alone. From varde-v28 each group heading (`.ix-group`) is the group name in the group colour followed by a thin line in the same colour to the right edge; no background, no left stripe, no subtitle (only the cards carry the stripe). A skin whose accent (`--red`) is close to `--gsafe` must set its own `--gsafe`, so the groups stay apart (Lett bris does).
- **Subheading notes (from build 34):** `SUB_NOTES` maps the id of a subheading on the standard list to a `UI` key; the text is shown under the subheading (`.subhead-note`). Used for Tabletter in Førstehjelpssett (`medNote`: read the package leaflet, ask a doctor or pharmacist). Medicine lines name no doses and recommend no choice between medicines.
- **Guide links:** `GUIDE_LINKS` maps standard list item ids to a guide (`'boots#ski'` opens that section). Links appear only on the standard list, as part of the app's basics; own lists get none. Changing the Norwegian text of a linked template line changes its id, so update the map at the same time.
- **List lock:** switched on when Utemodus is switched on; the earlier value is kept in `state.lockPrev` and restored when Utemodus is switched off (from varde-v30). No toast: Lås listen pulses three times instead (`pulseLock()`, class `pulse`, a fading outline; static outline with reduced motion; from varde-v31). `state.listLock` blocks ticking, switching trip types and the light day-hike view of bags (from varde-v23), in both normal and outdoor mode (Lås listen, next to Skjul pakket). The Turtype panel still opens (navigation) and shows a locked hint, with the chips dimmed (class `lk`). Other tabs keep working.
- **Header:** on the packing list, the whole header is one button (`#listBtn`) to Dine lister; on other pages it is a plain title (class `plain`). Long names drop the label, use up to two lines, then end with "…". In outdoor mode the header shows the Utemodus sign (`#hdrField`, the mountain icon in a circle in the Utemodus button's colour `--red`, no fill, status only until build 82; from build 82 a button that grows into «Avslutt utemodus», see «From testing (build 82)») and, at the right with a clear gap, the labelled Regnlås button (`#hdrLock`), with a 2 px outline and icon in rain blue and no fill (`--rain`: #74B4EA on dark headers, #1F5A8F on the light Lett bris header; the night light colour in Nattlys; from varde-v31); the "Dine lister" label in the list button is hidden in outdoor mode to give the name room (from varde-v30). **From build 80:** with Utemodus off the gear sits at the right end; in Utemodus the header is the plain page title («Pakkliste» on the list tab), then Regnlås, then the Utemodus sign at the right end (see «Innstillinger og Om Varde»).
- **Dine lister (layout from varde-v29):** the lists first (Standardliste, Dine egne lister, Delte lister, Ny liste and Sikkerhetskopi), then the settings as even sections (`.pg-sec` with an `.sec-lbl` heading and a thin line between): Utseende, Språk, Hjelp (only Slik bruker du Varde; the introduction opens from there), Start på nytt, Personvern, Om rådene (from build 32); the version as a small line at the very bottom (`.app-ver`, «Versjon 0.1.0 (bygg 32)»). New settings get a section the same way. **From build 80** the settings and these sections live in Innstillinger (the gear); Dine lister keeps the lists and the backup and ends with a row to Innstillinger (row removed in build 82, when the page got sections; see «From testing (build 82)»). New settings get a section there.
- **Kompass (layout from varde-v29):** four sections in the same style: the compass (no heading; «Kompasset er ikke startet» until started; from build 67 the north line and the Stjerner og planeter button), Himmelen (the flat-horizon note under the arc), Vær og varsler, Om kompasset.
- **Web links (from varde-v29):** every link that leaves the app is a row drawn by `webLink(url, label)`: name in `--link` colour and underlined, the address (`hostOf`) in small grey text, and an ↗ icon. Grouped on Kompass as «For der du er» and «Dine lenker». Never use a plain button for a web link.
- **Suggested links:** a guide can offer a link for Dine lenker with `data-act="sugLink" data-n data-u`: it opens the normal add-link boxes filled in, the user confirms, and the same address is never added twice; afterwards it shows «I Dine lenker». It changes data, so it is locked in Regnlås. Used in Fiske → Fiskekort og regler (`fishRulesHtml()`, texts in `UI.fishRules`, checked against Miljødirektoratet, Statsforvalteren and Mattilsynet in Oct 2026; no fee amounts or fines, as they change). `fishing#rules` scrolls to that section (from «Fiskekort (ferskvann)»).
- **Renamed template lines keep their ticks:** add the old and new id to the `moved` map after `migrate()` (Turdusj in v27, Biopose in v29; in v30 Vindsekk and Jervenduk both map to the merged line «Vindsekk eller Jervenduk (nødly, ta med én)», a tick on either is kept, and Redningsfolie got its new wording; in build 34 Smertestillende (paracetamol og/eller ibuprofen), Tennposer (ca. 4), which replaced Tennbriketter (4x), and Nylonsnor (forsterker lapping mot kant) 2x; Melatonin was removed; in build 35 Kuldekrem (mot tørr og sprukken hud, ikke mot frost)). Sekk is the first line in Generelt turutstyr (from varde-v30), where packing starts.
- **Backup (from build 32, 0.1.0):** the Sikkerhetskopi sheet (`backupSheet()`) opens with a warning box (`.bk-warn`, what deletes the data), then three equal buttons: Del (the phone's share menu; only shown when `navigator.share` exists), Lagre som fil (a `.json` download, `bkFileName()`) and Kopier. Del shares a `.txt` file with type `text/plain`, since Android's share sheet does not take `.json`, then falls back to sharing the text, then to a message pointing to the other two (build 33). Every success shows a check mark and a short word on the button for 3 s and a framed message right under the buttons (`.bk-msg.ok`); restore has its own message under its buttons. The text itself is folded under «Vis sikkerhetskopien som tekst». Restore takes pasted text or a chosen file. From build 73 (0.18.2) «Velg fil» is the main restore button, above the paste box (14 px space below it from build 74), and the paste button says «Legg til fra teksten»: long texts are often cut off when copied on a phone. Pasted text that starts like a backup (`{"app":"trip-checklist"`) but does not parse gets `bkCut` (cut off, use Velg fil) instead of `bkBad`; a chosen file always gets `bkBad`. From build 63 it also takes a pasted share link (`#share=` or `#note=`, found anywhere in the text): the sheet closes and the link is added through `importHash()`, the same path as opening the link (`checkShared()` only reads `location.hash` and calls it). `bkData()` = `{app:'trip-checklist', version:3, t, lists, notes, packW:{items}, links, plan:{calc, fuelCalc, foodCalc, wind}}`; settings (language, skin, theme) are left out. `bkRestore()` adds and never overwrites: identical lists (`listSig`), notes, Sekkvekt items and links already present are skipped; planner figures are only restored where the phone has none. Version 2 backups still restore. Bookkeeping: `personalSig()` hashes the personal content without ticks, folds or trip types; `save()` calls `bkTrack()`, which sets `state.bkDirtyT` when the content first differs from the last backup (`state.bkSig`, `state.bkLast`). Under the buttons on Dine lister: «Sist sikkerhetskopi: …», in warning style while there are changes not backed up. After 14 days with such changes, a calm banner at the top of Dine lister (Ta sikkerhetskopi, Senere = hidden for 7 days, `state.bkSnooze`); never in Utemodus. The installed app asks for persistent storage (`navigator.storage.persist()`) at start; nothing is sent.
- **Om rådene (from build 32):** `adviceTxt` in both languages, a section of Om Varde in Innstillinger (from build 80, whole, with the emergency line and the link to Når du trenger hjelp; before that the last section on Dine lister); the last intro card carries one sentence of it and the data safety sentence. No accept pop-up.
- **Dine lister:** all cards start folded. Lists received through a share link get `sharedIn: true` and are shown under Delte lister; Dupliser makes an own list.
- **Sky (Kompass):** sun arc and moon at a glance, then Sol and Måne details, then date and position. Moon phase, rise and set use standard low-precision formulas (`moonEq`, `moonIllum`, `moonDay`), offline.
- **Packing list tools:** Åpne alle / Lukk alle, Lås listen and Skjul pakket share one row in equal columns (`.sub-tools` grid, from varde-v27). The Turtype toggle and its open panel form one box (the toggle's outline continues round the chips). Category notes (`.cat-note`) fold with their category.

## Standing rule: links to Planlegg (from varde-v27)
Every link to a calculator in Planlegg looks the same, as the Vindkjøling link on Kompass: built with `planLink(tool, from)` (class `plan-link pc-<tool>`, `data-act="openPlan"`, `data-tool`, `data-from`): a light outline, the calculator's icon in its own colour (red in Nattlys) and the calculator's name. It is navigation (`data-nav`), so it works in Regnlås. `data-from` (`list`, `compass`, `guide`) sets `planFrom`, and every calculator's back button reads its label from `planBack()`; back itself uses history, so it returns to where you came from. Never make a plain button that opens a calculator.
- Standard list lines: `PLAN_LINKS` maps item ids to a calculator (Turdusj → Vannblanding, Brensel → Drivstoff, Turmat → Mat, Hundemat → Mat, Hundesekk → Sekkvekt; from build 37 the Sekk line links to the Pakk sekken guide instead, and the Sekkvekt link sits in that guide). Standard list only, and never on a line that has a guide link. Changing the Norwegian text of a linked line changes its id, so update the map at the same time.
- Guide text: write `[[plan:<tool>]]` in its own paragraph; the guide renderer replaces it with `planLinks()` (Vinterråd: Mat, Vindkjøling, Drivstoff). A new text guide that uses markers must pass its HTML through `planLinks()`.
- Look for natural links when adding content: a list line or guide paragraph about food, fuel, pack weight, water mixing or wind chill should link to its calculator.

## Night light and screen light (from varde-v30)
- The light row under Utemodus has three equal buttons (`.lt-btn`, `data-light="red|green|fire"`), handled by delegated touch and pointer events, not `data-act`. A tap on Rødt or Grønt nattlys colours the app (`state.night` plus `state.nightHue` `'red'|'green'`, one at a time; body classes `night` and `ngreen`); a tap on Bål only shows a hint. Holding any of them for 1 s opens the screen light.
- Grønt nattlys uses pure green only (no red or blue in any colour), so the screen uses its green subpixel (about 520–530 nm on OLED). Texts say red keeps night vision and is best before sleep, green is easier to read at low brightness. Every page must be checked in both Rødt and Grønt nattlys.
- Screen light (`#slight`, `openLight()`, `closeLight()`): fills the whole screen with pure red (#ff0000), pure green (#00ff00) or the Bål flicker, asks for fullscreen (works on Android, not on iPhone), keeps the screen on, blocks every tap, and the Android back button does not close it (`slMode` in `popstate`). It closes only when the handle is slid to the end of the track. The note and the slide track show for 3 s when the light opens, then fade out over 1 s (class `calm`, no fade with reduce motion); a touch anywhere brings them back for 4 s (`slShow()`), and while they are hidden the handle takes no touch, so the first touch can never unlock (from build 34). A web app cannot set the screen brightness, so the light says so. Nødmodus will reuse it (white light and SOS).
- Bål flicker limits: brightness drifts to a new random level every 150–400 ms, eased each frame, only between 70 and 100 %, over a slow 3.2 s breathing; no hard flashes. With reduce motion set on the phone it is a steady amber. Keep these limits if it is ever changed. From build 55 Bål is drawn by the `Fire` module (see Bål below); the limits apply to its background glow.
- The light buttons are not `data-nav`: like other switches they are locked in Regnlås.

## Bål (from build 55, 0.12.0)
- Built and tried as a chat prototype first (Oct 2026). All of it lives in one scope, `const Fire = (() => { … })()`, so its many short names never clash with the app; the app uses only `Fire.start(canvas)`, `Fire.stop()`, `Fire.addWood()` and `Fire.resumeAudio()`. `openLight('fire')` shows `#slight` with the class `fire`, then starts the fire on `#slFireCv` (a canvas under the note and the track); `slStop()` calls `Fire.stop()`, so every way of closing the light stops it.
- **Picture:** about 30 frames a second (kinder to the battery). A glow keeping the flicker limits above; a bed of embers; ten uneven flame tongues that lick and lean in a slow wind, each with its own height, width and place, and a brighter core; small pieces of flame now and then break off a tip and fade; sparks rise. Wider and taller when the screen is wider than tall (a phone turned sideways, or mirrored to a TV).
- **Burns down:** over 45 minutes (`BURN_MS`) to dark red embers; sound, sparks and flames follow `life`. **Adding wood:** one steady finger held 1.5 s on the fire (a second finger, sliding more than 12 px or lifting early cancels it, so rain cannot do it): the flames grow back over 10 s, sparks and a crackle, a short buzz on Android, and the burn-down starts over. The note at the top says so (`fireWood`, `white-space:pre-line`). On the fire the note and track use light text with a shadow, so they stay readable over embers; in landscape they sit small in the bottom right corner.
- **Sound:** generated with Web Audio (no files, works offline): low rumble, hiss, random crackles and the odd louder snap. Starts silent and rises over 12 s. Suspended when the app goes to the background, resumed when it comes back; a touch resumes it where the phone wants a gesture (`Fire.resumeAudio()` at the end of the hold that lights it, and on touches on the light).
- **Guests:** eight, one at a time, in random order and never the same twice in a row: the first after 1.5–3.5 min, then every 4–9 min, none while the fire is nearly out. Troll, nisse, troll couple (tails crossing in a heart), owl on a branch (eyes catch the firelight), fox trotting past, bat, reindeer and ghosts. Each is drawn fully opaque on its own layer (`off`), then laid over the fire with one opacity, so overlapping parts never show seams; colour `#160600` at 92 %. The reindeer stands behind the flames (`behind:true`, drawn under them, a little fainter, facing away from the fire, placed so muzzle and antlers always stay on the screen; the short tail is part of the body outline). The ghosts grow out of sparks and glow, with see-through eyes; each stays 10–12 s, rises slowly and fades out over 3.5 s (from build 57, 0.12.2). They fade in and out over seconds; nothing flashes.
- **Firelight, eyes and movements (from build 79, 0.21.0; tried in a chat prototype with a Før / Etter switch, 20 Nov):** after a guest is drawn on `off`, `firelight()` lays it on a second sheet (`lit`) with a faint warm glow from the flames (`source-atop`, a radial gradient from the brightest part of the fire) and a rim on the side facing the fire: the silhouette minus itself moved away from the fire (`rimc`, `destination-out`), in three passes from wide and faint to thin and bright, so the edge is soft without a canvas blur filter (Safari lacks it). The direction comes from `guestAt()` (roughly where each guest is); the light follows the fire's brightness (`bri`) and `life`. The reindeer, across the fire, gets a stronger front glow and no rim; the ghosts get no firelight. Eyes are collected while drawing (`eye()`, into `EYES`, in device pixels) and drawn last with `lighter`: shine with a halo (fox green-gold while it stands; reindeer once its head is up, blue Nov–Mar and gold Apr–Oct after Stokkan et al. 2013, `REIN_EYE`), or a small glint (`glint`: troll, nisse, the owl's two eyes); the troll pair has none, so they feel calm. Movements: the troll's tail sways, the nisse's pompom bobs, the owl tilts and now and then turns its head, the fox stops near the middle for a few seconds (its stride follows the distance, so its legs stand still; visit 12 s), the troll pair breathe and her hair ends sway, the reindeer flicks an ear. The extra drawing covers the whole sheet while a guest is on screen (5–22 s every 4–9 min); check the frame rate on an older phone before limiting it to a box. **Redrawn:** the troll pair, seen from behind: he turns his head in profile with a troll nose and a shaggy mop, she has long wavy hair with curled ends and a small flower (no bun), and the pair is mirrored on the left side so his nose points at the fire; the nisse has a small round nose; the reindeer is traced from the owner's own photo (points in the photo's pixels, `RP()`, ground at 0 and withers 0.54 up), antlers 30 % larger and seated on the skull with short pedicles, neck, head and antlers turning together about the shoulder as it raises its head, placed so the antlers stay on the screen while it grazes. **Test hook:** `Fire.show(kind)` brings that guest at once and after each visit, `Fire.show()` goes back to chance, `Fire.guest` names the guest on screen; the app's script is wrapped, so a test reaches them only through `window.__vardeTest.Fire`, set when a test defines `window.__vardeTest` before the app starts (nothing is exposed otherwise).
- **Burned out (from build 56, 0.12.1):** as the last embers die the sound fades to silence. Two minutes after the fire is out (`OUT_MS`) soft glowing Z's rise from the embers (one every 3 s, about 7 s each), then it sleeps: one last still picture of the embers with a faint «z Z Z», the drawing and the sound stop, and `updateWake()` lets go of the screen even in Utemodus (`Fire.sleeping`, reported through the callback passed to `Fire.start`), so the phone turns the screen off as usual. The light stays open; holding the screen to add wood wakes everything. Sliding the handle still puts it out.
- **Reduce motion:** a steady amber, no flames, sparks or guests; the sound still plays. It never burns down, so it never sleeps.
- **TV:** no cast button (it would need Google's receiver registration and network, and not work on iPhone); the help text tells people to turn the phone and mirror the screen.

## Sorting in Rediger (from build 44, 0.9.0)
- Only in Rediger (`editing`; `main.editing`), so Utemodus and Regnlås are untouched. Each row has a grip (`.grip`, ⠿, left end, `touch-action:none`): the drag starts when the finger moves 3 px. Long press on the row (`SORT_HOLD` 400 ms, cancelled if the finger moves more than `SORT_SLOP` 8 px, so a swipe still scrolls) lifts it with a short vibration (`navigator.vibrate`, skipped where unsupported).
- Rules: rows move within their own category only. A main item moves as a block with its sub-items (`sortBlock()`) and lands between blocks; a sub-item moves alone and never lands first (`sortMin()`). `sortUnits()` gives the places it can land, `sortApply()` the new order. Only `cat.items` order changes; ids, ticks and the storage key do not.
- While dragging (`sortDrag`): the block floats (`.lifted`), the other rows slide aside with transforms, the page auto-scrolls within `SORT_EDGE` 64 px of the header or tab bar, a non-passive `touchmove` listener stops the page from scrolling under the finger, and the long-press menu and text selection are off. The click that ends a drag is swallowed (not one on #toast). `busy()` holds a pending reload while dragging.
- Letting go saves through `withUndo()` («Flyttet: …» with Angre). Escape, `pointercancel` or the phone's back button put everything back (back stays in Rediger).
- Keyboard and screen readers: the grip is a button («Flytt …»); arrow up and down move one step by the same rules.

## True north and Stjerner og planeter (build 67, 0.16.0)
- **Magnetic or true north (checked 16 Nov 2026):** both phones give magnetic north. Chrome on Android's `deviceorientationabsolute` comes from the magnetometer, and the iPhone's `webkitCompassHeading` is relative to magnetic north; neither browser corrects for declination. Before this build the sun and moon marks (true azimuths) were off by the declination: about 3° in Stavanger, 14° in Alta, 17° in Kirkenes.
- **Decided (16 Nov):** with a saved position the compass shows true north, as on maps. `magDecl(lat, lon, date)` computes the declination on the phone from the World Magnetic Model 2025 (`WMM_COF`, degree 12, main field and secular variation, NOAA/BGS, public domain; valid 2025.0–2030.0). `declNow()` caches it per position and day; `onOrient()` adds it to the heading. The line `#cNorth` (`northLine()`) under the direction says «Sann nord · misvisning 14° Ø», or «Magnetisk nord · hent posisjonen for sann nord» without a position. Om kompasset has a section Sann nord, and Kart og kompass → Misvisning one sentence about it. **Before 2030:** replace `WMM_COF` and `WMM_EPOCH` with WMM2030 (the coefficient file from NOAA NCEI), and update the reference values in the `kompass` smoke test.
- **Stjerner og planeter** (view `stars` on Kompass, `renderStars()`, opened by the button `data-act="cStars"` under the sun and moon chips; navigation, so `data-nav`): the compass fills the page (`.rose.big`, viewBox -52…372, same centre 160,160) with an outer ring (r 150–212) showing what is above the horizon now: 21 bright stars (`STARS`, J2000 positions, Polaris included; precession ignored, under 0.5°), Venus, Jupiter, Mars and Saturn (`PLANETS`, JPL approximate Keplerian elements, `planetRaDec()`), and the moon (`moonAzAlt`). `skyObjects()` and `azAlt()` give azimuth from true north and altitude. Dots at r 162 turn with the dial; names (`.stl`) are placed by `placeStarLabels()` (called from `uprightMarks()`): centred on one of two rings at the top and bottom, running inwards from the edge at the sides, so nothing leaves the ring; a name with no free place is left out. Stars in `--ink`, planets in `--sun`, so Nattlys works. Below: a line for daylight or twilight (`starSay()`, sun above −0.833° or −12°), the list «Over horisonten nå» (`starList()`: direction, height and fists of 10°), a note and a link to Nattehimmelen. Redrawn every minute (`skyTimer`). Names in `UI.starN` (Polarstjernen / Polaris, Alfa Centauri / Alpha Centauri as in the guides). Nothing is stored and nothing is sent.
- **Checked against:** pygeomag with the official WMM2025 coefficient file (declination equal to within 1e-6°), and PyEphem for stars and planets (within 0.5°). Smoke tests `kompass`: the reference values in Node (the sky code is cut out of `index.html`, since the app's closure hides it from the page), true and magnetic north with a simulated sensor event, the star view in both languages at a fixed time, and Nattlys on Kompass and the star view.
- **Milky Way band, its centre and the moon (build 69, 0.17.0)** in Stjerner og planeter. The galactic plane (b = 0, IAU 1958 system; pole RA 192.8595°, Dec +27.1283°, l of the celestial pole 122.9319°, J2000, values as in Astropy) is sampled every 2° (`galRaDec()`, `milkyWay()`) and run through `azAlt()` like the stars. `mwBand()` draws it in the grey ring (`#skyBand`, under `#skyStars`, inside the dial so it turns with it) on the half above the horizon: blurred arcs (`#mwBlur`) in `--ink`, stronger where it stands higher and towards Sagittarius (l = 0), plus a short mark across the outer line at each horizon point. Never paled for daylight or light nights: it shows where the Milky Way is, not whether it can be seen (decided 17 Nov). Not drawn when its highest point is under 10° (`MW_LOW`); the list then says it lies low. List rows first: Melkeveien (`mwRow()`: horizon points with the more northerly first, «fra N til S», «fra Ø til V»; the highest point, or «høyest nesten rett over deg» above 80°; a bright-moon note when the moon is up and more than half lit), then Melkeveiens sentrum (Skytten) (`gcRow()`, `galCentre()`: Sagittarius A*, RA 266.417°, Dec −29.008°; position when up, else below now with its highest point, «bare så vidt» when it never gets above 5°, «aldri» when it never rises; in Norway at most about 3°, never north of 61° N). The moon in its phase fills the middle of the dial (`centreMoon()`, `moonGlyph(…, 44, south, 48)`, `#stMoon`, outside the dial so it stays upright, faded below the horizon); the reading line stops at its edge and the centre dot is left out in this view. Smoke test `melkeveien`: Stavanger 17 Nov 22:00 (W to E, nearly overhead, centre 2°, two horizon marks, moon in the middle), Sydney 15 Jul 22:00 (centre overhead, Sentrum on the ring), Tenerife 1 Mar 03:20 (low, no band), both languages.
- **Names, list groups and the Milky Way in the dial (build 75, 0.19.0).** *Names on the ring:* each `.stl` holds a thin line (`.stll`, `--muted`) and the name with an outline in `--bg` (`paint-order="stroke"`), so the red north line never runs through a name; `starMarks()` puts the names before the dots, so a dot is never hidden by a name. `placeStarLabels()` places each name from its own dot: at the sides 14 px above or below it (no longer from the outer edge); for a close pair (dots under `PAIR_DEG`, 9°, apart) the higher dot's name goes above and the lower one's below (before this build the brighter star's name always went above, so «Rigel» stood by Aldebaran's dot). ## Private notes and encryption (build 70, 0.18.0)
- **Crypto core:** Web Crypto only, offline, no libraries. Password → key with PBKDF2-SHA-256, `PRIV_ITER` (600,000) rounds, 16 random bytes of salt (OWASP Password Storage Cheat Sheet); the password is normalised with NFKC first (`pwNorm`), so æøå typed on another keyboard still matches; nothing else is changed (no trimming, emoji allowed). Content: AES-GCM, 256-bit key, a fresh 12-byte IV for every save. `CRYPTO_OK` (secure context with `crypto.subtle`) hides every private, password and backup-password option when it is false. Minimum password length `PW_MIN` (8) for all three uses. No PIN code: it waits for fingerprint unlock (WebAuthn PRF) after the final address.
- **Private notes:** envelope encryption. One random 32-byte data key encrypts the notes; it is stored only wrapped with the password key in `state.priv = {v:2, kdf:'pbkdf2-sha256', iter, salt, iv, wrap}` (v 1 before build 91; see build 91). A wrong password fails the GCM check; no check value is stored. A private note in `state.notes` is `{id, t, pin?, c?, rcv?, shT?, priv:1, iv, ct, title:'', text:''}`; `ct` holds `{ti, tx}`. **Plain text of a private note never goes into `state`, `localStorage` or `sessionStorage`**: while unlocked, the data key (`privRaw`, `privKey`) and the opened texts (`privOpen`, a Map by id) live in memory only. Always read a note through `noteView(n)` (the note, its opened copy, or null while locked); `noteSeal()` encrypts and empties title and text. The method and round count are stored with the data, so a raised `PRIV_ITER` takes effect at the next unlock (`privUnlock` re-wraps; only the wrap changes).
- **Locking:** `privLock()` after `PRIV_IDLE_MS` (5 min) without a pointerdown or key, and after `PRIV_BG_MS` (60 s) in the background (`visibilitychange`); Lås nå on Dine lister. An open edit of a private note is sealed and saved first; a sheet marked `panel.dataset.priv` (the share sheet of a private note, which shows its text) is closed.
- **Wrong tries:** after `PRIV_FREE_TRIES` (5) wrong passwords a 30 s wait, doubled for each further one, at most an hour (`state.privFail = {n, until}`, stored with `persist()`, so a restart does not reset it; a right password deletes it). Not in the backup.
- **Rules:** opening, editing, pinning, colour, sharing and Fjern privat need it unlocked; deleting a locked note does not. Utemodus and Regnlås never ask for the password (`privEnsure()` returns false there): a locked note shows the lock and `privField`. Søk only covers Guider; a later note search must skip locked notes. A locked note in the list shows «Privat notat» with `LOCK_IC` (closed lock), the date, no preview and no tags; an open one shows its title with `LOCK_OPEN_IC` (shackle lifted, from build 72). ## Standing rule: rain lock and navigation
Anything that only changes what you see (changing page, back, opening bags and guides, fold-out sections, folding list categories, the Turtype panel, the list button in the header, links that leave the app) carries the attribute `data-nav`; `<summary>` elements count automatically. In the rain lock these work during the navigation window and restart its 3 seconds. Anything that changes data (ticks, switches, typing, editing lists) never gets `data-nav` and stays locked. Every new feature must follow this.

## Security (from build 58, 0.12.3)
- **Content-Security-Policy:** a `<meta http-equiv="Content-Security-Policy">` tag at the top of `<head>`: `default-src 'self'`; scripts only from the app itself plus the inline script by its SHA-256 hash; styles `'self' 'unsafe-inline'` (the templates use many `style="…"` attributes, which cannot be hashed); images `'self' data:` (the favicon and the Berg grain are data: URIs); fonts, fetches, the service worker and the manifest `'self'`; no media, objects or frames; `base-uri` and `form-action` `'none'`. Inline event handlers (`onclick="…"`, `onerror="…"`) do not run under it: use listeners (the knot photo fallback is a capturing `error` listener on `document`).
- **The hash must follow the script:** any change to the inline `<script>` changes its hash, and with a stale hash the app does not start at all. After editing the script run `node tools/csp-hash.js --write` (or `npm run csp`), which writes the new hash into the tag; `node tools/csp-hash.js` only checks. The smoke test fails on a stale hash, and from build 59 a red test stops publishing (the previous version stays live), but still run it before committing. A chat that builds `index.html` must do the same (any SHA-256 of the script text between `<script>` and `</script>`, base64, works).
- **Imported data gets the app's own ids:** everything that comes from a backup file or a share link gets fresh ids from `uid()` (`cloneList`, `unpackList`, `receiveNote`, and from build 58 restored notes and Sekkvekt items in `bkRestore()`), because ids are written into HTML attributes without escaping. Sekkvekt items already present with the same name, weight, category and marks are skipped, so restoring the same file twice adds nothing. Planner figures from a file pass through `bkPlanClean()`: only finite numbers, true/false, the known choices (`mode`, `fuel`, `season`) and the nested figures under their known keys. Look-ups with imported keys use `own()` (own properties only), never a plain `MODES[k]`, so `constructor` or `__proto__` never count as a trip type, icon or link. Any other text from stored or imported data goes through `esc()`.

## The three crypto items from 17 Nov (build 91, 0.25.0)
- **Password strength hint:** `pwStrength(pw)` gives 0 (under `PW_MIN`), 1 weak, 2 fair, 3 strong, offline: weak for a password in `PW_COMMON` (Norwegian and English, also with digits or symbols round it and simple swaps such as 0 for o, through `leet()` and `core()`), three or fewer different characters, or mostly running characters or a keyboard row (`PW_ROWS`, forwards or backwards); then strong from 20 characters, four words, or 16 with three kinds of characters; fair from 13, three words, or 10 with three kinds. `pwMeterHtml(id)` + `pwMeter(input, box)` draw the line (`.pw-m`, three bars and `pwWeak` / `pwFair` / `pwStrong`; the words carry the meaning, the bars only repeat it). Only where a new password is chosen: `pwSheet` with `twice` (`#pw1M`), the share sheet (`#shPwM`) and the backup box (`#bkPw1M`); never on unlock. A warning, never a block.
- **AAD (`gcmEnc` / `gcmDec` take an optional `aad`):** share links with a password are version 2 (`LINK_ITER[2]`), with the 30-byte header (version, z flag, salt, IV) as AAD; password backups are `enc:2` with `bkAad()` (app, enc, kdf, iter, salt); the private-note wrap `state.priv` is `v:2` with `wrapAad()`; each private note has its own random tag `n.ck` (12 bytes, b64u), checked as `'varde-note|' + ck` (`noteAad()`), so an encrypted text cannot be moved to another note without its tag. Not covered (security review 22 Nov, accepted): someone who can write to storage, or a crafted backup on the same-key restore path, can move the whole set (`ck`, `iv`, `ct`) to another note, or delete `ck` so the note opens as an untagged pre-91 note; that only puts one of the user's own texts under another note's pin, colour and date, and anyone who can write to storage could do worse. The tag cannot be the note id, since restore gives new ids. Version 1 links, `enc:1` backups, `v:1` wraps and notes without `ck` still open. `privUnlock()` upgrades the wrap to v 2 and seals again every note without `ck`. Restore keeps `ck` with `iv` and `ct`. Side effect: a backup made before the upgrade has another wrap, so restoring it on the same phone asks for its password once (as after Bytt passord).
- **The sender's name inside the encryption:** a private note's `ct` holds `{ti, tx, rn?}`; `n.rcv` keeps only `{t}` (the dashed outline and the date). `noteSeal(n, title, text, key, rn)` takes the name from `rn`, else `n.rcv.n`, else the opened copy, and drops `n.rcv.n`; `privOpen` holds `{title, text, rn?}`; `noteView()` puts the name back into `rcv` for the open note; Fjern privat (`notePubl`) puts it back in plain form. Stored notes with a plain name move it inside at the next unlock.
- Smoke tests in `privat`: «the strength line where a new password is chosen (0.25.0)», «old private notes open and are upgraded; texts cannot be swapped; the sender's name is encrypted (0.25.0)» (the old-format data is made in Node with Web Crypto as builds 70–90 made it; the swap fails without the note tag), «links and backups: version 2 checks the header; old ones still open (0.25.0)». ## Standing rules
1. Every change to `index.html` raises the build number: `APP_BUILD` in `index.html` and `CACHE` in `sw.js` together (e.g. `APP_BUILD = 33` and `'varde-b33'`), so installed apps fetch the update. The visible version `APP_VERSION` follows 0.x.y and changes only when a version is released to testers: middle number for an update with new features, last number for fixes only. 0.1.0 (build 32) is the first test version; 1.0.0 is the first version outside testing, with the final name. Both are shown under Hjelp as «Versjon 0.1.0 (bygg 32)». (Before build 32 the two were one string, `varde-v1` to `varde-v31`.)
2. Never change the storage `KEY` (`outdoor-lists-v1`) in `index.html`, not even if the app is renamed. People have their own lists on their phones; changing it would wipe them. Template changes only affect newly created lists.
3. Keep Norwegian and English in step: every text and template line exists in both languages. All Norwegian text in the app is Bokmål; a source in Nynorsk can be used, but its wording is never carried into the app (from build 36).
4. No brand names or organisation symbols in the app or the lists (except the user's deliberate choices: Jervenduk, DNT key / Hyttetur (DNT), varsom.no, yr.no, inatur.no for fishing licences (from varde-v29); agreed link exceptions for later guides: norgeskart.no, artsdatabanken.no, helsenorge.no, felleskatalogen.no, nrr.org (from build 50, for now)).
5. Field-friendly design: comfortable tap targets, no gestures that need precision, undo for destructive actions. Must keep working offline.
6. Keep the app a single self-contained `index.html`. Check the JavaScript before committing (e.g. extract the `<script>` and run `node --check`).
7. Every change reaches `main` through a pull request (from build 59; the ruleset for `main` requires one and a passing smoke test), with a short, clear message describing the change.
8. Keep commit summaries under 50 characters; put details in the extended description.
9. Anything new that stores personal data must be included in the backup (`bkData`, `bkRestore`, and `personalSig` if it is content people would miss), and restore must add without overwriting.

## Publishing (from build 59, 0.12.4)
- **GitHub Pages source: GitHub Actions** (Settings → Pages), not «Deploy from a branch». `.github/workflows/smoke.yml` has two jobs: `smoke` runs on every pull request and every push to `main`; `deploy` (`needs: smoke`) runs only for a push to `main` after `smoke` passed, uploads the repository root (hidden files and folders left out, no Jekyll) with `upload-pages-artifact` and publishes it with `deploy-pages` to the `github-pages` environment. A failed test means nothing is published and the previous version stays live. Deployments queue (`concurrency: pages`), never cancel each other.
- **Ruleset for `main`** (Settings → Rules → Rulesets): pull request required (0 approvals, since the owner works alone), status check `smoke` required, deletions and force pushes blocked, no bypass. The GitHub web upload therefore uses «Create a new branch for this commit and start a pull request»; merge when `smoke` is green.
- **Actions are pinned to full commit SHAs** with the tag in a comment (`uses: actions/checkout@<sha> # v7.0.1`). Never use a bare tag or branch. `.github/dependabot.yml` checks GitHub Actions monthly and opens one grouped pull request with new SHAs; merge it when `smoke` passes. Playwright in `package.json` is pinned by hand, not by Dependabot.
- **Minimal permissions:** the workflow sets `permissions: {}` at the top; `smoke` gets `contents: read`, `deploy` gets `contents: read`, `pages: write` and `id-token: write`. Checkout uses `persist-credentials: false`. A new workflow follows the same pattern.
- A new file the app needs is published automatically (the whole root goes up), but it must still be listed in `ASSETS` in `sw.js` to work offline.

## Lessons learned
- **Focus moved by a sheet (22 Nov, after build 88):** `fra testing 0.24` failed once on `main` with the weight typed into the Sekkvekt name field. Sheets move focus to their first field 30 ms after opening, and Playwright's `fill()` types into whatever has focus at that moment, so a fill into another field straight after opening can land in the first one. Tests wait for the first field to have focus (`toBeFocused()`) before filling any field of a new sheet, as `newNote()` already did. Not a problem on a phone, where nobody types within 30 ms.
- **Flaky password test on GitHub (20 Nov, after build 80):** «a shared note with a password needs it on the other phone» failed on GitHub twice in three runs with the second password field empty right after filling, while it passed every time locally, even with the CPU slowed six times. The helper `pwOk()` now fills both fields again until they hold the password (`toPass`); the rest of the test still checks that the note became private and encrypted. If a password field ever clears itself on a phone, look at the sheet being redrawn while it opens.
- The smoke test on GitHub runs in Playwright's Chrome Headless Shell, not full Chrome. From Chrome 153 `DeviceOrientationEvent.requestPermission()` exists in Chromium too (as on the iPhone), and the headless shell denies it, so Start kompasset stops at «ikke tillatt» there while it passes locally in full Chrome (build 67). Tests that start the compass answer it with an init script (`requestPermission` → `'granted'`, as a user tapping Allow). The app itself handles both answers.
- `body` uses the classes `field`, `night`, `ngreen`, `locked`, `listlock`, `navopen` and `notlist`, and the attribute `data-skin`. Never reuse these names for other elements: a clash once made the whole page wider than the screen.
- `main` has the class `wrap`, so its bottom spacing for the tab bar is set on `main.wrap`. After any layout change, check that the last content on every page ends above the tab bar.
- The Android back button is handled with the History API (`go`, `goBack`, `popstate`). New screens and sheets must use `go()` or `openSheet()` so back keeps working.
- The body element carries `data-skin`, so click handlers must never match `closest('[data-skin]')` without a class (use `.skin-btn[data-skin]`); a generic match caught every click in the app once.
- Sheets that close and are followed by navigation must not leave a history entry behind: `go()` reuses a closed sheet's entry.
- All interface text for one language shares a single object in `UI`, so check that a new key is not already in use before adding it (a guide called `winter` once overwrote the season label `winter`).
- Opening or closing the rain lock's navigation window must not redraw the page (`lockUi()` only), or open sections and the scroll position are lost.
- The app remembers the last page (`state.lastNav`) and reopens there after a reload or when it comes back from the background; a fresh start opens Pakkliste instead (from build 48, see Start state). `render()` falls back to the main page if that page no longer exists.
- Regnlås (rain lock, Utemodus only, also from the lock button in the header) blocks every change and all navigation while scrolling still works. Holding Naviger (1 s) opens navigation for 3 seconds (`NAV_MS`), renewed on each page change; holding Lås opp (1 s) switches it off. Both use `holdButton`, which handles touch events directly. The rain lock is saved (`state.rainLocked`), because Chrome on Android lets the back button close the app even while it is locked; on reopening, the app is still locked.

## Name
"Varde" is a working name through testing; the final name (and maybe an own domain) is decided before 1.0. All app texts take the name from `APP_NAME` in `index.html` (UI strings use `${APP_NAME}`), so a rename means changing `APP_NAME`, the three places in `<head>` (`<title>`, `application-name`, `apple-mobile-web-app-title`), `manifest.webmanifest` and the README, and optionally the `CACHE` prefix in `sw.js`. Never write the name directly in a new text. Never change the storage `KEY`. Keep the repository name `varde`: the GitHub Pages address and share links contain `/varde/`.
