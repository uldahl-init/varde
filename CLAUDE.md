# Varde – project notes for Claude Code

Varde (working name, may change) is an offline web app (PWA) for planning and packing outdoor trips: day hikes and shorter multi-day hikes with tent or under the open sky. Owner: Svein Atle. Published with GitHub Pages from the `main` branch, root folder.

## Files
- `index.html` – the whole app (HTML, CSS and JavaScript in one file). No build step, no external dependencies apart from Google Fonts.
- `sw.js` – service worker that makes the app work offline. Contains the cache name `CACHE` with the build number (`varde-b33` and so on).
- `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` – installation on the phone.
- `README.md` – short user guide (Norwegian).

## Structure of index.html
- `UI` – all interface text, in `en` and `no`. Every new string must be added in both.
- `friluftsliv(L)` – the template list (main sections in the order Før tur, Overnatting, Generelt turutstyr, Tøy, Matlaging, Mat; Tøy above Matlaging from varde-v28), written as `[Norwegian, English]` pairs. Prefixes in item strings: `> ` = sub-item, `* ` = included in the light day-hike view, `@key ` = links to a bag list.
- Main sections, trip modes (`mode:`), and bag lists (`bag:true`: Forberedelser, Førstehjelpssett, Reparasjonssett, Personlig pleie). A non-sub item followed by sub-items is rendered as a subheading and is not counted.
- `MODES` (trip types), `CAT_ICONS` (section icons), `SKINS` (Fjell, Mose, Fjord, Sommereng, Berg, Lett bris; the last two from varde-v27). Berg has a faint stone grain (`--grain`, an inline SVG noise, so it works offline) on the page and header, switched off in Nattlys. Lett bris (from varde-v28): cream page, light sky-blue header with dark header text, summer-blue accent, own `--gsafe` (orange). A light header sets `--hd-btn` (list button background) and `--hd-track` (progress bar track) so they stay visible; Nattlys resets both.
- Tabs: Pakkliste, Notater, Planlegg (Mat, Drivstoff, Sekkvekt, Vannblanding, Vindkjøling), Guider (grouped: Ferdigheter i felt (Dyrespor last, from build 43): Knuter, Tarp, Sove godt på tur, Pakk sekken, Kart og kompass, Fiske, Bål; Vær og sikkerhet: Solbriller, Vinterråd, Topptur og skred, Møte med dyr (from build 45); Utstyr og vedlikehold: Telt, Reparasjoner på tur, Brennerplate, Skalltøy, Fjellsko, Ski: smøring og feller, Mobilen på tur; Helse og nød: Medisiner på tur (from build 42); Sove godt på tur and Ski from build 36, Pakk sekken and Reparasjoner på tur from build 37, Kart og kompass from build 38), Kompass.
- **Tapping the tab you are on (from build 36):** on a sub-page it goes to that tab's main view, as before; on the main view it scrolls to the top (`scrollTopSmooth()`, smooth, instant with reduce motion). Navigation only: ticks and fold states are untouched, and in Regnlås it renews the navigation window.
- Utemodus (outdoor mode): larger targets, editing locked, Lås listen switched on, screen kept on, strict tap filter, the Utemodus sign and Regnlås in the header, and the light row: Rødt nattlys, Grønt nattlys and Bål (from varde-v30; Angre and the Regnlås chip under Utemodus were removed then).
- Data is stored in `localStorage` under `KEY`.

## Data model (from varde-v7)
- `state.v = 2`. Older stored data is converted once by `migrate()`; lists that match the built-in template become the standard list (ticks, trip types and views kept), anything else is kept as an own list. Never remove the migration.
- **Standard list:** built from `friluftsliv(lang)` on the fly by `stdList()`, always in the app language. Its ticks, trip types, light view and folded sections live in `state.std` (`done`, `modes`, `light`, `open`). Item ids are `std:<section key>:<Norwegian text in lower case>`, so ticks survive a language switch; changing the Norwegian text of a template item resets that item's tick.
- **Own lists:** `state.lists`. `state.main` is `'std'` or the id of the own list shown on the front page (Bruk som hovedliste). `list.tripType` makes it appear under Turtype (Legg til i turtype). The two roles rule each other out: making a list the main list switches its trip type off, and making the main list a trip type, or switching its main role off, falls back to the standard list; switching it on stores `'L:<list id>'` in the main list's `modes`, and its sections are added to the main list.
- Always change ticks, folding and light view through `setDone`, `setOpen` and `setLight`, which handle both kinds of list.
- **Sharing:** `#share=<code>` links carry a packed list (`packList`/`unpackList`), deflate-compressed when the browser supports it (`z` prefix) or plain (`j`). Nothing is stored on a server.
- **Introduction:** shown once (`state.introDone`), and from Guider → Slik bruker du Varde.
- **Fuel planner:** litres boiled per person per day (`USE_KEYS`, defaults in `WATER_DEFAULT`, drinking water is always boiled) times fuel per litre (`FUELS[x].perL`: gas 15 g, petrol 30 ml, spirit 50 ml; own figure in `fuelCalc.perLc`). Water from snow multiplies everything by `SNOW_BOIL` (2.5). Day hike mode (`fuelCalc.mode = 'day'`) hides the table and uses one figure (`dayL`). The summary at the top shows the whole calculation.
- **Food planner:** meals per person per day with their energy side by side; the gauge at the top shows one full day against zones (`KZONES`: summer red below 2000 kcal, yellow below 3000, green above; winter 2500 / 3500).
- **Guide drawings:** own drawings (no licence needed) in `guides/`, loaded inline by `loadSvgs()` and coloured with `--sb-*` variables (defined on `.sb-fig`, with dark, Rødt and Grønt nattlys values; `--sb-heavy` from build 37 for the heavy zone in Pakk sekken); precached in `sw.js`. From build 37 a text guide section can hold a drawing: `<figure class="sb-fig"><div data-svgsrc="guides/<file>.svg"></div></figure>` in its HTML; `renderTextGuide()` calls `loadSvgs()` and passes every section through `planLinks()`. Drawings carry no text (both languages) and use `var(--sb-surface)` instead of white, so the night lights stay pure red or green. Drawings in build 37: `firesteel.svg` (Bål → Tennstål), `pack-zones.svg` (Pakk sekken), `edge-repair.svg` (Reparasjoner på tur); build 38: `compass-parts.svg` (numbered, with a `.fig-legend` list in the same figure) and `compass-steps.svg` (Kart og kompass). Web links in guide text: write `[[web:<url>|<label>]]`; `renderTextGuide()` turns it into a `webLink()` row through `webMarks()` (from build 38; used for norgeskart.no).
- **Notater (notepad, from varde-v18):** `state.notes` = `[{id, title, text, t}]`, newest first by `t` (last edited). Pages: `notes` tab, one note at `note:<id>`. Opening a note is navigation (`data-nav`); new, edit and delete are data changes and are hidden in Utemodus. Delete uses `withUndo`. Lists no longer have their own notes: `notesFromList()` moves any list notes into the notepad (once for stored lists, `state.notesMoved`; and for lists received by share link or restored from backup), titled with the list name. The backup carries `notes` beside `lists`.
- **Notater from build 41 (0.6.0):** *Edit in place:* on a note's own page, Rediger, the title or the text (`data-act="editNote"`, `data-f`) turns the note into fields in place (`#neTitle`, `#neText`, the text box grows with `growArea()`), with Avbryt and Lagre below (`noteCancel`, `noteSave`). The draft lives in `noteEdit` (never stored) and is dropped when you leave the note or Notater; Lagre only changes `t` when something changed, and an empty title and text are not saved. The pop-up `askNote()` is only for Nytt notat. A tap while text is selected does not start editing. *Fest øverst:* `n.pin = true` (`notePin`, the same button unpins); `notesSorted()` puts pinned notes first, each part newest first; a small pin (`PIN_IC`) shows in the list and on the note. *Del:* `noteShare` → `askShareNote()`: the sheet shows exactly what is sent (title and text), the warning about personal information and an optional name field, empty by default and never remembered; then Rediger først (opens the edit in place) or Del. The link is `#note=<code>` with `{v:1, k:'note', ti, tx, n?}` packed by `encodePacked()` (shared with list links); nothing else goes in. On a successful share `n.shT` is set. Opening a link runs `receiveNote()` from `checkShared()`: it shows the note and asks «Legg til i notatene dine?»; an identical note already there is opened instead. A received note gets `n.rcv = {n:name, t}`. *Tags:* `noteTags()` gives «Delt fra [navn] · [dato]» or «Mottatt [dato]» and «Delt [dato]», in the list and on the note. Received notes have a dashed outline in `--muted` (class `rcv`), never the accent colour; the tag says the same in words. Pin, edit, share and delete are hidden in Utemodus and locked in Regnlås (no `data-nav`). Backup: the notes carry `pin`, `rcv` and `shT`; `noteMeta()` copies them on restore, and `personalSig()` counts `pin` and `rcv` only when present, so older backups are not flagged as changed.
- **Sekkvekt (pack weight, from varde-v19):** `state.packW` = `{unit:'g'|'kg', items:[{id, name, g, cat, cons, dog}]}`; weights are always stored in grams, `unit` only changes display and input. Items come from the main list (`pickFromList()`, food items marked as consumable) or are typed in (`askWeightItem()`, category from the main list's sections or Annet). The summary shows the total of your pack, base weight and consumables (when anything is marked consumable), a subtotal per category, and the dog pack separately. Always go through `packW()`.
- **Dog in the planners:** food planner shows kcal per meal next to each meal name (`data-mk`, from varde-v22); `foodCalc.dog`, `dogs`, `dogG` (g per dog per day, times days including the reserve day; not part of the kcal gauge). Fuel planner `fuelCalc.dog`, `dogL` (litres per day), only when water comes from snow: added once per day, not per person, times `SNOW_BOIL`.
- **Start på nytt (from varde-v20):** button on Dine lister, right after Hjelp and before Personvern (from varde-v27), hidden in Utemodus. Clears all ticks (standard list, own lists, bags), all trip types, open/closed sections (back to default, including the Kompass fold-outs in `state.folds`; from varde-v26), folds the Turtype panel, makes the standard list the main list, and turns off Utemodus, Regnlås, Skjul pakket and Lås listen. Never deletes lists, notes, Sekkvekt, planner figures or settings (language, skin, theme, Nattlys). Runs through `withUndo`.
- **Knot pictures:** an entry in `KNOT_FILES` can be one file or an array of files (several pictures on one card, as for Åttetallsknute). Every picture needs a line in `KNOT_CREDITS` (two lines with the same `k` are fine) and a place in `sw.js`.
- **Fonts (from varde-v22):** Barlow 400/600 and Barlow Condensed 600 are bundled in `fonts/` (latin subset, from Fontsource; SIL Open Font License, `fonts/OFL.txt`) and loaded with `@font-face`, so the app looks the same offline. No Google Fonts or other outside requests. New font files must be added to `sw.js`.
- **Text guides:** plain text guides (Skalltøy, Fjellsko with Skistøvler, Telt, Tarp, Bål, Topptur og skred, Sove godt på tur (`sleep`), Ski: smøring og feller (`ski`, sections `wax` and `skins`), Pakk sekken (`pack`, section `zones`), Reparasjoner på tur (`repair`, sections `patch`, `pad`, `pole`); Kart og kompass (`mapcompass`, sections `parts`, `steps`, `decl`, `maps`; from build 38, linked from the list line «Kart og kompass i vanntett kartmappe» and from a button under Om kompasset on Kompass); Bål has the section `steel` (Tennstål) from build 37) live in `GUIDE_TXT` (`no` and `en`, each `{title, short, sub, secs}`; a section can carry a third value as its id) and are drawn by `renderTextGuide()`. Kept in their own object, not in `UI`, so their keys cannot clash with interface text. A new text guide only needs an entry in both languages and a place in `GUIDE_GROUPS`.
- **Søk i Guider (from build 39, 0.5.0):** on the Guider page a magnifier button (`.gs-btn`, `data-act="gsOpen"`, 48 px) sits at the right of the intro line «Korte påminnelser til turen.». Tapping it swaps that line for the search field (`#gsInput`, `.gs-field`) with focus and the keyboard up; × (`gsClose`) clears and closes it, an empty field closes by itself when it loses focus, and tapping the Guider tab or leaving Guider clears the search (`gsReset()`). State lives in `gSearch` (`{open, q}`), never in `state` and never stored. From two letters (`GS_MIN`) the groups are replaced by a count and results (`gsShow()`, only `#gsBody` is redrawn while typing, so the field keeps focus); below that the groups show. Matching (from build 40, 0.5.1): both languages whatever the setting, case ignored, parts of words match, words not meanings. A match in the current language is shown as usual; a match found only in the other language shows that language's snippet with a small tag (`.gs-lang`, «NO» or «EN») and still opens the section in the current language. `guideIndex(lang)` builds the plain text per guide (title, short, intro, sections) once per language (`gsCache[lang]`), using `gsPlain()` (markers and tags out, entities decoded in an inert document). Each result (`.gs-hit`, left stripe in the group colour, guide name, section name, snippet with every match in `<mark>`) is one section, or the guide's top for a hit in its title or intro; at most `GS_MAX` (50) are shown. A result is navigation (`data-nav`, `data-act="gsHit"`): it opens the guide, then `openHit()` unfolds the `<details>` whose summary contains the section heading and scrolls it into view; Back returns to the open search with the same text. Typing, opening and closing the field are locked in Regnlås (the magnifier and field are greyed); results already on screen work in the navigation window.
- **Rule: every guide and section is searchable.** A text guide in `GUIDE_TXT` is searched automatically. A guide with its own renderer (Knuter, Fiske, Solbriller, Vinterråd, Brennerplate, Mobilen på tur) is listed in `old` inside `guideIndex()`: add any new text it shows there, and give every new guide with its own renderer an entry. Section headings in the index must match the `<summary>` text the guide draws, or the result cannot unfold its section. Sections are matched between the languages by position, so every guide keeps the same sections in the same order in Norwegian and English (the smoke test checks the counts).
- **Guider order (agreed 17 Oct 2026):** groups are ordered by how often Guider is opened directly: Ferdigheter i felt, Vær og sikkerhet, Utstyr og vedlikehold, and later Helse og nød (mostly reached by links). Within a group, the most-used guide first, and guides that link to each other side by side. A new guide goes into an existing group by when it is used: out on the trip → Ferdigheter i felt; before the trip or at home → Utstyr og vedlikehold. A new group only for a clearly new use with at least three guides. Each guide sits in one group only; link between guides instead of copying text (`data-act="openGuide" data-guide data-sec`).
- **Guide groups:** `GUIDE_GROUPS` sets the order and group of every guide on the Guider page. Order (from varde-v21): Ferdigheter i felt first (what you look for in a hurry), then Vær og sikkerhet, and Utstyr og vedlikehold last (what you check back home). Each group has a colour (`--gc`: `--lichen`, `--red`, `--gsafe`) shown as a stripe and a group heading, never colour alone. From varde-v28 each group heading (`.ix-group`) is the group name in the group colour followed by a thin line in the same colour to the right edge; no background, no left stripe, no subtitle (only the cards carry the stripe). A skin whose accent (`--red`) is close to `--gsafe` must set its own `--gsafe`, so the groups stay apart (Lett bris does).
- **Subheading notes (from build 34):** `SUB_NOTES` maps the id of a subheading on the standard list to a `UI` key; the text is shown under the subheading (`.subhead-note`). Used for Tabletter in Førstehjelpssett (`medNote`: read the package leaflet, ask a doctor or pharmacist). Medicine lines name no doses and recommend no choice between medicines.
- **Guide links:** `GUIDE_LINKS` maps standard list item ids to a guide (`'boots#ski'` opens that section). Links appear only on the standard list, as part of the app's basics; own lists get none. Changing the Norwegian text of a linked template line changes its id, so update the map at the same time.
- **List lock:** switched on when Utemodus is switched on; the earlier value is kept in `state.lockPrev` and restored when Utemodus is switched off (from varde-v30). No toast: Lås listen pulses three times instead (`pulseLock()`, class `pulse`, a fading outline; static outline with reduced motion; from varde-v31). `state.listLock` blocks ticking, switching trip types and the light day-hike view of bags (from varde-v23), in both normal and outdoor mode (Lås listen, next to Skjul pakket). The Turtype panel still opens (navigation) and shows a locked hint, with the chips dimmed (class `lk`). Other tabs keep working.
- **Header:** on the packing list, the whole header is one button (`#listBtn`) to Dine lister; on other pages it is a plain title (class `plain`). Long names drop the label, use up to two lines, then end with "…". In outdoor mode the header shows the Utemodus sign (`#hdrField`, the mountain icon in a circle in the Utemodus button's colour `--red`, no fill, status only, no action) and, at the right with a clear gap, the labelled Regnlås button (`#hdrLock`), with a 2 px outline and icon in rain blue and no fill (`--rain`: #74B4EA on dark headers, #1F5A8F on the light Lett bris header; the night light colour in Nattlys; from varde-v31); the "Dine lister" label in the list button is hidden in outdoor mode to give the name room (from varde-v30).
- **Dine lister (layout from varde-v29):** the lists first (Standardliste, Dine egne lister, Delte lister, Ny liste and Sikkerhetskopi), then the settings as even sections (`.pg-sec` with an `.sec-lbl` heading and a thin line between): Utseende, Språk, Hjelp (only Slik bruker du Varde; the introduction opens from there), Start på nytt, Personvern, Om rådene (from build 32); the version as a small line at the very bottom (`.app-ver`, «Versjon 0.1.0 (bygg 32)»). New settings get a section the same way.
- **Kompass (layout from varde-v29):** four sections in the same style: the compass (no heading; «Kompasset er ikke startet» until started), Himmelen (the flat-horizon note under the arc), Vær og varsler, Om kompasset.
- **Web links (from varde-v29):** every link that leaves the app is a row drawn by `webLink(url, label)`: name in `--link` colour and underlined, the address (`hostOf`) in small grey text, and an ↗ icon. Grouped on Kompass as «For der du er» and «Dine lenker». Never use a plain button for a web link.
- **Suggested links:** a guide can offer a link for Dine lenker with `data-act="sugLink" data-n data-u`: it opens the normal add-link boxes filled in, the user confirms, and the same address is never added twice; afterwards it shows «I Dine lenker». It changes data, so it is locked in Regnlås. Used in Fiske → Fiskekort og regler (`fishRulesHtml()`, texts in `UI.fishRules`, checked against Miljødirektoratet, Statsforvalteren and Mattilsynet in Oct 2026; no fee amounts or fines, as they change). `fishing#rules` scrolls to that section (from «Fiskekort (ferskvann)»).
- **Renamed template lines keep their ticks:** add the old and new id to the `moved` map after `migrate()` (Turdusj in v27, Biopose in v29; in v30 Vindsekk and Jervenduk both map to the merged line «Vindsekk eller Jervenduk (nødly, ta med én)», a tick on either is kept, and Redningsfolie got its new wording; in build 34 Smertestillende (paracetamol og/eller ibuprofen), Tennposer (ca. 4), which replaced Tennbriketter (4x), and Nylonsnor (forsterker lapping mot kant) 2x; Melatonin was removed; in build 35 Kuldekrem (mot tørr og sprukken hud, ikke mot frost)). Sekk is the first line in Generelt turutstyr (from varde-v30), where packing starts.
- **Backup (from build 32, 0.1.0):** the Sikkerhetskopi sheet (`backupSheet()`) opens with a warning box (`.bk-warn`, what deletes the data), then three equal buttons: Del (the phone's share menu; only shown when `navigator.share` exists), Lagre som fil (a `.json` download, `bkFileName()`) and Kopier. Del shares a `.txt` file with type `text/plain`, since Android's share sheet does not take `.json`, then falls back to sharing the text, then to a message pointing to the other two (build 33). Every success shows a check mark and a short word on the button for 3 s and a framed message right under the buttons (`.bk-msg.ok`); restore has its own message under its buttons. The text itself is folded under «Vis sikkerhetskopien som tekst». Restore takes pasted text or a chosen file. `bkData()` = `{app:'trip-checklist', version:3, t, lists, notes, packW:{items}, links, plan:{calc, fuelCalc, foodCalc, wind}}`; settings (language, skin, theme) are left out. `bkRestore()` adds and never overwrites: identical lists (`listSig`), notes, Sekkvekt items and links already present are skipped; planner figures are only restored where the phone has none. Version 2 backups still restore. Bookkeeping: `personalSig()` hashes the personal content without ticks, folds or trip types; `save()` calls `bkTrack()`, which sets `state.bkDirtyT` when the content first differs from the last backup (`state.bkSig`, `state.bkLast`). Under the buttons on Dine lister: «Sist sikkerhetskopi: …», in warning style while there are changes not backed up. After 14 days with such changes, a calm banner at the top of Dine lister (Ta sikkerhetskopi, Senere = hidden for 7 days, `state.bkSnooze`); never in Utemodus. The installed app asks for persistent storage (`navigator.storage.persist()`) at start; nothing is sent.
- **Om rådene (from build 32):** `adviceTxt` in both languages, last section on Dine lister; the last intro card carries one sentence of it and the data safety sentence. No accept pop-up.
- **Dine lister:** all cards start folded. Lists received through a share link get `sharedIn: true` and are shown under Delte lister; Dupliser makes an own list.
- **Sky (Kompass):** sun arc and moon at a glance, then Sol and Måne details, then date and position. Moon phase, rise and set use standard low-precision formulas (`moonEq`, `moonIllum`, `moonDay`), offline.
- **Packing list tools:** Åpne alle / Lukk alle, Lås listen and Skjul pakket share one row in equal columns (`.sub-tools` grid, from varde-v27). The Turtype toggle and its open panel form one box (the toggle's outline continues round the chips). Category notes (`.cat-note`) fold with their category.
- **Åpne alle / Lukk alle (from varde-v25):** a small chip before Lås listen on the packing list (`data-act="foldAll"`, `data-nav`), shown when the page has more than one category. It opens all categories, or folds all when every one is open, through `setOpen`, so the choice is remembered. Bag pages show one category, always open, so it does not appear there. Trip type sections are part of `visibleCats()`, so they follow it. Exception (from varde-v26): the Turtype panel (`modesOpen`) never opens with Åpne alle; Lukk alle folds it if it is open.
- **Kompass fold-outs (from varde-v25):** «Sol og måne» (Sol and Måne details) and «Dato og posisjon» are `<details class="fold" data-fold="sky|pos">`, open by default; the state is saved in `state.folds` (`foldOpen()`), and the sun arc, the big line and the moon line stay above them. «Legg til egen lenke» has a dashed outline with a + and a hint line.
- **Privacy (from varde-v25):** the app makes no requests to other sites (only its own files); the position is fetched only on the button, stored in `state.pos` and never sent (weather and avalanche links carry no coordinates). Texts: `posNote` on Kompass, the last intro card, and Personvern under Hjelp on Dine lister with a link to the repository. Keep them true: anything new that sends data must change these texts.
- **Weather and warnings:** chosen from the saved position (`region()`, `NO_POLY`, `AVALANCHE`), plus the user's own links in `state.links`. Check the addresses now and then.
- **Updates:** `sw.js` fetches pages with `cache:'no-cache'`, registration uses `updateViaCache:'none'`, and the page reloads once when a new version takes over. From build 40 (0.5.1) the app also asks for a new version when it comes back to the front with a connection (`visibilitychange`, at most every 30 s), since Android often keeps it in memory instead of starting it again. The reload waits while a sheet, the introduction, the full-screen light or a text field is in use (`reloadWhenSafe()`), and the app reopens on the same page (`state.lastNav`).
- **Sun times:** calculated offline (`sunPos`, `sunDay`) from `state.pos` (GPS) and the date.
- **Sun and moon on the compass rose (from varde-v23):** two chips under Hold retningen switch them, both on by default (`state.skyNow`, `state.skyRiseSet`, read through `skyOn()`). Sol og måne nå: the sun with rays and the moon in its phase (`skyNowMarks`, `moonAzAlt`, `moonGlyph`), faded below the horizon, redrawn every minute. Soloppgang og solnedgang: a half sun on a horizon with an arrow up or down, plus a short line at the rim for the exact direction (`sunMarks`, `riseSetMark`), for the chosen date. Sun symbols use `--sun` (amber; red in Nattlys), never the north red. Symbols carry the class `upr` and are turned back by `uprightMarks()` so they stay upright as the dial turns. The chips are switches, so they stay locked in Regnlås.
- **Fiske guide (from varde-v24):** fishing knots live in their own guide (`fishing`, in Ferdigheter i felt between Tarp and Bål from varde-v26, so Knuter and Tarp sit together; from build 36 Sove godt på tur sits between Tarp and Fiske), so the Knuter page keeps its own warning and count. Cards in `UI.fishKnots` (both languages, same shape as `knots`), pictures in `FISH_KNOT_FILES`, credits in `FISH_KNOT_CREDITS`; drawn by `renderKnots('fishing')` with the shared `knotCards()` and `knotCredits()`. Linked from the Fiske trip type (Kroker, Svivler / sene). More fishing content goes on this page.
- **Wide knot drawings:** an SVG whose viewBox is wider than 1.6 : 1 gets the class `wide` and fills the card width (max 220 px high) instead of the fixed 220 px height.
- **Knot images:** separate SVG files in `knots/`, listed in `KNOT_FILES` (by knot index) and credited in `KNOT_CREDITS`, shown on the Knuter page. They keep their own licence (see `knots/LICENSE.md`), use `var(--knot-line)` and `var(--knot-fill)` for colours, and are precached in `sw.js`. Only add images that have been checked against the knot tied in real rope, and always add the credit and the licence row.

- **Planlegg cards (from varde-v26):** each calculator has its own icon (`PLAN_ICONS`) and colour (`--pc-food`, `--pc-fuel`, `--pc-weight`, `--pc-water`, `--pc-wind`, light and dark values; all red in Nattlys), shown as a solid outline and a round icon. The icon carries the meaning, never colour alone. The colours stay clear of the Guider group colours. A new calculator gets an icon, a colour and a `pc-<key>` class.
- **One meaning per style:** left stripe = group or category (Guider, later note categories); the group colour with the heart icon on a Guide link = a guide in Helse og nød; solid colour outline with icon = which calculator (Planlegg); underlined link-coloured name with address and ↗ = a web page outside the app; dashed outline = add something (Legg til egen lenke) or received from someone else (Notater, from build 41; in `--muted`, never the accent colour); light grey outline with a calculator's icon in its colour and its name = a link to that calculator (Planlegg links).
- **Vindkjøling (wind chill, from varde-v26):** `tool:wind`, `renderWind()`, `state.wind` = `{t, v}` (°C, m/s). Formula: the NWS and Environment Canada wind chill index (2001), WCT = 13.12 + 0.6215·T − 11.37·V^0.16 + 0.3965·T·V^0.16 with V in km/h (m/s × 3.6), valid at 10 °C or colder and from 4.8 km/h; outside that the air temperature is shown with a note. Frostbite bands (`windRisk`): −28 to −39: 10–30 min; −40 to −47: 5–10 min; −48 to −54: 2–5 min; −55 and colder: under 2 min; over 50 km/h a note that it can go faster. Inputs have − / + steppers and a ± button (phone number keyboards often lack a minus). Opened from Planlegg, from the Vindkjøling link in Vær og varsler on Kompass and from Faresignaler for kuldeskader in Vinterråd (Planlegg links, see below); links back to Vinterråd. Steppers and typing change data and stay locked in Regnlås; the buttons that open it are navigation.

## Standing rule: links to Planlegg (from varde-v27)
Every link to a calculator in Planlegg looks the same, as the Vindkjøling link on Kompass: built with `planLink(tool, from)` (class `plan-link pc-<tool>`, `data-act="openPlan"`, `data-tool`, `data-from`): a light outline, the calculator's icon in its own colour (red in Nattlys) and the calculator's name. It is navigation (`data-nav`), so it works in Regnlås. `data-from` (`list`, `compass`, `guide`) sets `planFrom`, and every calculator's back button reads its label from `planBack()`; back itself uses history, so it returns to where you came from. Never make a plain button that opens a calculator.
- Standard list lines: `PLAN_LINKS` maps item ids to a calculator (Turdusj → Vannblanding, Brensel → Drivstoff, Turmat → Mat, Hundemat → Mat, Hundesekk → Sekkvekt; from build 37 the Sekk line links to the Pakk sekken guide instead, and the Sekkvekt link sits in that guide). Standard list only, and never on a line that has a guide link. Changing the Norwegian text of a linked line changes its id, so update the map at the same time.
- Guide text: write `[[plan:<tool>]]` in its own paragraph; the guide renderer replaces it with `planLinks()` (Vinterråd: Mat, Vindkjøling, Drivstoff). A new text guide that uses markers must pass its HTML through `planLinks()`.
- Look for natural links when adding content: a list line or guide paragraph about food, fuel, pack weight, water mixing or wind chill should link to its calculator.

## Night light and screen light (from varde-v30)
- The light row under Utemodus has three equal buttons (`.lt-btn`, `data-light="red|green|fire"`), handled by delegated touch and pointer events, not `data-act`. A tap on Rødt or Grønt nattlys colours the app (`state.night` plus `state.nightHue` `'red'|'green'`, one at a time; body classes `night` and `ngreen`); a tap on Bål only shows a hint. Holding any of them for 1 s opens the screen light.
- Grønt nattlys uses pure green only (no red or blue in any colour), so the screen uses its green subpixel (about 520–530 nm on OLED). Texts say red keeps night vision and is best before sleep, green is easier to read at low brightness. Every page must be checked in both Rødt and Grønt nattlys.
- Screen light (`#slight`, `openLight()`, `closeLight()`): fills the whole screen with pure red (#ff0000), pure green (#00ff00) or the Bål flicker, asks for fullscreen (works on Android, not on iPhone), keeps the screen on, blocks every tap, and the Android back button does not close it (`slMode` in `popstate`). It closes only when the handle is slid to the end of the track. The note and the slide track show for 3 s when the light opens, then fade out over 1 s (class `calm`, no fade with reduce motion); a touch anywhere brings them back for 4 s (`slShow()`), and while they are hidden the handle takes no touch, so the first touch can never unlock (from build 34). A web app cannot set the screen brightness, so the light says so. Nødmodus will reuse it (white light and SOS).
- Bål flicker limits: brightness drifts to a new random level every 150–400 ms, eased each frame, only between 70 and 100 %, over a slow 3.2 s breathing; no hard flashes. With reduce motion set on the phone it is a steady amber. Keep these limits if it is ever changed.
- The light buttons are not `data-nav`: like other switches they are locked in Regnlås.

## Sorting in Rediger (from build 44, 0.9.0)
- Only in Rediger (`editing`; `main.editing`), so Utemodus and Regnlås are untouched. Each row has a grip (`.grip`, ⠿, left end, `touch-action:none`): the drag starts when the finger moves 3 px. Long press on the row (`SORT_HOLD` 400 ms, cancelled if the finger moves more than `SORT_SLOP` 8 px, so a swipe still scrolls) lifts it with a short vibration (`navigator.vibrate`, skipped where unsupported).
- Rules: rows move within their own category only. A main item moves as a block with its sub-items (`sortBlock()`) and lands between blocks; a sub-item moves alone and never lands first (`sortMin()`). `sortUnits()` gives the places it can land, `sortApply()` the new order. Only `cat.items` order changes; ids, ticks and the storage key do not.
- While dragging (`sortDrag`): the block floats (`.lifted`), the other rows slide aside with transforms, the page auto-scrolls within `SORT_EDGE` 64 px of the header or tab bar, a non-passive `touchmove` listener stops the page from scrolling under the finger, and the long-press menu and text selection are off. The click that ends a drag is swallowed (not one on #toast). `busy()` holds a pending reload while dragging.
- Letting go saves through `withUndo()` («Flyttet: …» with Angre). Escape, `pointercancel` or the phone's back button put everything back (back stays in Rediger).
- Keyboard and screen readers: the grip is a button («Flytt …»); arrow up and down move one step by the same rules.
- Not yet: moving rows between categories and reordering whole categories (possible later).

## Standing rule: sources (from build 36, replaces the build 35 wording)
Safety texts are checked against official or scientific sources and the owner's experience; sources are kept in the project notes, never shown in the app. Use official or scientific sources only (for example SNL, Miljødirektoratet, Forsvaret, Helsedirektoratet, NIH, Mattilsynet, Varsom/NVE), never popular or commercial sites, retailers, gear makers or magazines. ## Standing rule: rain lock and navigation

## Standing rules
1. Every change to `index.html` raises the build number: `APP_BUILD` in `index.html` and `CACHE` in `sw.js` together (e.g. `APP_BUILD = 33` and `'varde-b33'`), so installed apps fetch the update. The visible version `APP_VERSION` follows 0.x.y and changes only when a version is released to testers: middle number for an update with new features, last number for fixes only. 0.1.0 (build 32) is the first test version; 1.0.0 is the first version outside testing, with the final name. Both are shown under Hjelp as «Versjon 0.1.0 (bygg 32)». (Before build 32 the two were one string, `varde-v1` to `varde-v31`.)
2. Never change the storage `KEY` (`outdoor-lists-v1`) in `index.html`, not even if the app is renamed. People have their own lists on their phones; changing it would wipe them. Template changes only affect newly created lists.
3. Keep Norwegian and English in step: every text and template line exists in both languages. All Norwegian text in the app is Bokmål; a source in Nynorsk can be used, but its wording is never carried into the app (from build 36).
4. No brand names or organisation symbols in the app or the lists (except the user's deliberate choices: Jervenduk, DNT key / Hyttetur (DNT), varsom.no, yr.no, inatur.no for fishing licences (from varde-v29); agreed link exceptions for later guides: norgeskart.no, artsdatabanken.no, helsenorge.no, felleskatalogen.no).
5. Field-friendly design: comfortable tap targets, no gestures that need precision, undo for destructive actions. Must keep working offline.
6. Keep the app a single self-contained `index.html`. Check the JavaScript before committing (e.g. extract the `<script>` and run `node --check`).
7. Commit straight to `main` with a short, clear message describing the change.
8. Keep commit summaries under 50 characters; put details in the extended description.
9. Anything new that stores personal data must be included in the backup (`bkData`, `bkRestore`, and `personalSig` if it is content people would miss), and restore must add without overwriting.

## Lessons learned
- `body` uses the classes `field`, `night`, `ngreen`, `locked`, `listlock`, `navopen` and `notlist`, and the attribute `data-skin`. Never reuse these names for other elements: a clash once made the whole page wider than the screen.
- `main` has the class `wrap`, so its bottom spacing for the tab bar is set on `main.wrap`. After any layout change, check that the last content on every page ends above the tab bar.
- The Android back button is handled with the History API (`go`, `goBack`, `popstate`). New screens and sheets must use `go()` or `openSheet()` so back keeps working.
- The body element carries `data-skin`, so click handlers must never match `closest('[data-skin]')` without a class (use `.skin-btn[data-skin]`); a generic match caught every click in the app once.
- Sheets that close and are followed by navigation must not leave a history entry behind: `go()` reuses a closed sheet's entry.
- All interface text for one language shares a single object in `UI`, so check that a new key is not already in use before adding it (a guide called `winter` once overwrote the season label `winter`).
- Opening or closing the rain lock's navigation window must not redraw the page (`lockUi()` only), or open sections and the scroll position are lost.
- The app remembers the last page (`state.lastNav`) and reopens there; `render()` falls back to the main page if that page no longer exists.
- Regnlås (rain lock, Utemodus only, also from the lock button in the header) blocks every change and all navigation while scrolling still works. Holding Naviger (1 s) opens navigation for 3 seconds (`NAV_MS`), renewed on each page change; holding Lås opp (1 s) switches it off. Both use `holdButton`, which handles touch events directly. The rain lock is saved (`state.rainLocked`), because Chrome on Android lets the back button close the app even while it is locked; on reopening, the app is still locked.
